// capabilities

Built for professional security work

Eight assessment disciplines accessible through a consistent MCP interface.

  • AI-Assisted Security Orchestration

    Coordinate security tools and assessment workflows through MCP-compatible AI clients.

  • Network Reconnaissance

    Integrations for network discovery, port scanning, service enumeration and infrastructure analysis.

  • Vulnerability Assessment

    Identify and investigate vulnerabilities with supported scanners and security intelligence tools.

  • Web & API Security

    Assess web applications and APIs with HTTP inspection, fuzzing and authentication testing.

  • Active Directory Security

    Assess Active Directory and Windows environments through AD and SMB integrations.

  • Cloud & Container Security

    AWS, Azure, GCP, container, Kubernetes and infrastructure-as-code security assessments.

  • Digital Forensics & Reverse Engineering

    Memory analysis, binary inspection, firmware research and digital evidence workflows.

  • MCP AI Client Integration

    Expose registered tool interfaces to MCP-compatible clients, including Claude Desktop.

// installation

Get started

Install the Python dependencies and configure your MCP client. Security tools must be installed separately on the host.

Clone & install dependencies · bash
git clone https://github.com/0x7AK7/RedVector.git
cd RedVector
 
python3 -m venv .venv
source .venv/bin/activate
 
python -m pip install --upgrade pip
pip install -r requirements.txt
Standalone MCP operation · bash
bash start_redvector.sh
Backend only · bash
python redvector_server.py

The MCP launcher uses stdio. Once configured, Claude Desktop launches start_redvector.sh automatically. Do not start the launcher separately for that session.

// design philosophy

Why RedVector

Architecture and design principles behind the framework.

PRINCIPLE 01

MCP-compatible tool interfaces

Registered handlers expose security tools to AI clients through the Model Context Protocol.

PRINCIPLE 02

Cross-discipline security tooling

Network, web, cloud, Active Directory, forensics and reverse engineering in one framework.

PRINCIPLE 03

Extensible Python backend

An open Python/Flask codebase for custom integrations and assessment workflows.

PRINCIPLE 04

Structured security workflows

Decision, workflow and execution components organize assessments.

PRINCIPLE 05

Process monitoring and reporting

Monitor execution, cache results and collect telemetry for long-running assessments.

PRINCIPLE 06

Kali Linux compatibility

Designed to work with the tooling commonly found on Kali Linux.

PRINCIPLE 07

Open-source development

Source code, issues and releases are public on GitHub under the MIT license.

PRINCIPLE 08

Controlled deployment

Deployment guidance covers authorized testing and keeping the backend off the public internet.
